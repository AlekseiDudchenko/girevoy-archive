# Гиревой архив

Публичный архив результатов соревнований по гиревому спорту.
Данные извлекаются из PDF-протоколов моделью, администратор проверяет и публикует.

- `docs/decisions.md` — принятые решения и правки к требованиям
- `docs/schema.md` — пояснения к схеме
- `docs/roadmap.md` — план реализации по шагам
- `migrations/0001_init.sql` — схема D1
- `seeds/` — справочники и демонстрационные данные
- `scripts/gen_demo.py` — генератор демо-данных

## Быстрый старт

```sh
npm run db:local     # локальная база SQLite со схемой, справочниками и демо-данными
sqlite3 .local/girevoy.db
```

На Cloudflare:

```sh
npm run db:create    # id из вывода вписать в wrangler.toml
npm run db:migrate
npm run db:seed
```

## Демо на GitHub Pages

`.github/workflows/pages.yml` собирает статический снимок на демо-данных при каждом
пуше в `main`. Чтобы он заработал, один раз включите Pages:
**Settings → Pages → Source → GitHub Actions**.

Это витрина интерфейса. Рабочий сайт живёт на Cloudflare: там страницы собираются
из D1 тем же кодом (`src/render.js`), а Pages отдаёт только заранее отрендеренный
снимок — админки, поиска по базе и свежих данных на нём нет.

## Демо-данные

4 вымышленных соревнования, 16 категорий, 96 результатов, 60 спортсменов.
Три турнира опубликованы, четвёртый ждёт сверки и содержит открытые проблемы —
на нём разрабатывается экран сверки.

Покрывают неудобные случаи: одноручный длинный цикл на 30 минут, зачёты
любителей и новичков, весовая категория «+95», отложенная эстафета,
клубы с разнобоем написаний, спортсмены с выступлениями на нескольких турнирах.

Соревнования и спортсмены **вымышленные**. Генератор детерминирован:
`npm run demo:gen` даёт тот же файл.
