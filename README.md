# Все гири — архив российского гиревого спорта

**Все гири** — открытый архив результатов соревнований по гиревому спорту.

Проект собирает опубликованные протоколы соревнований, приводит их к единой структуре и делает данные удобными для поиска, сравнения и просмотра истории выступлений.

Сайт проекта: **https://vsegiri.com**

---

## О проекте

Официальные результаты гиревого спорта обычно опубликованы в виде отдельных PDF- и Excel-протоколов. В таком виде сложно ответить даже на простые вопросы:

- где и когда выступал спортсмен;
- как менялись его результаты со временем;
- кто был его тренером;
- в каких соревнованиях он участвовал;
- как менялись весовые категории, дисциплины и спортивные разряды;
- какие спортсмены представляли регион или тренера;
- где найти оригинальный протокол конкретного соревнования.

Цель проекта — превратить разрозненные документы в **единый исторический архив**, сохранив при этом связь каждого результата с первоисточником.

## Что уже умеет архив

На сайте доступны:

- **архив соревнований** с фильтрацией по году, уровню, городу и другим параметрам;
- **страницы соревнований** с датой, местом проведения, статистикой и ссылками на протокол;
- **единая база результатов** с поиском, сортировкой и фильтрацией;
- **страницы спортсменов** со всеми найденными выступлениями;
- **графики динамики результатов** по сопоставимым сериям;
- **история личного веса** по данным протоколов;
- **список спортсменов** с регионом, годом рождения, разрядом и статистикой;
- **страницы тренеров** и список связанных с ними спортсменов;
- **исторические связи тренер–спортсмен**, привязанные к конкретным соревнованиям;
- **единая модель персон**: один человек может быть спортсменом, тренером, судьёй или спортивным деятелем;
- **нормализация регионов и написаний имён** без потери исходного текста протокола;
- **объединение дублей спортсменов и персон** с сохранением старых URL и алиасов;
- **публичные отметки исправлений** для подтверждённых ошибок в исходных протоколах;
- **ссылки на оригинальные и архивные копии протоколов**;
- светлая и тёмная темы;
- SEO-страницы спортсменов, персон и соревнований для обычного веб-поиска.

Архив постоянно пополняется. Отсутствие результата на сайте не означает, что спортсмен не участвовал в соревновании: часть исторических протоколов ещё не внесена.

## Цели проекта

### 1. Сохранить историю

Старые протоколы постепенно исчезают с сайтов федераций и организаторов. Архив должен сохранить не только итоговые цифры, но и происхождение данных.

### 2. Сделать результаты доступными

Пользователь должен находить спортсмена, соревнование или тренера за несколько секунд, а не просматривать десятки PDF-файлов вручную.

### 3. Показать спортивную траекторию

Отдельный результат интересен сам по себе, но намного полезнее видеть историю:

**спортсмен → соревнования → результаты → дисциплины → тренеры → регионы → годы.**

### 4. Не скрывать ошибки первоисточника

Спортивные протоколы содержат опечатки и внутренние противоречия. Проект не переписывает историю молча: исходное значение сохраняется, а подтверждённое редакционное исправление отмечается отдельно.

### 5. Оставаться проверяемым

Для данных важно происхождение. По возможности результат должен вести к исходному документу, из которого он был получен.

## Принципы работы с данными

Главный риск проекта — правдоподобная ошибка в цифре или неверное объединение двух разных людей.

Поэтому в проекте действуют несколько принципов:

- исходные значения из протокола сохраняются рядом с нормализованными;
- неизвестные регионы и неоднозначные персоны не нормализуются молча;
- подтверждённые ошибки источника хранятся как отдельные исправления;
- объединение персон выполняется явно и проверяемо;
- исторические связи восстанавливаются по конкретным протоколам, а не по текущему состоянию карточки;
- оригинальный протокол остаётся главным первоисточником.

Извлечение данных автоматизируется, но автоматизация не считается безошибочной. Для числовых результатов особенно важна сверка с первоисточником.

# Техническая часть

## Архитектура

Production-версия сайта построена как **статический сайт на Cloudflare Pages**.

Схема сборки:

```text
протоколы / JSON
       │
       ▼
data/*.json
       │
       ├── генераторы и проверки
       ▼
локальная SQLite
       │
       ▼
SSR-подобный статический рендеринг
       │
       ▼
dist/
       │
       ▼
Cloudflare Pages
       │
       ▼
vsegiri.com
```

Публичный production-сайт не требует постоянно работающего backend или базы данных.

SQLite используется во время сборки для выполнения тех же запросов, на которых построены страницы.

В репозитории также сохранён прототип **Cloudflare Worker + D1**. Он является прямым путём перехода к динамической архитектуре, если в будущем понадобятся админка, API, авторизация, серверный поиск или частые обновления без полной пересборки.

## Технологии

- JavaScript / Node.js;
- Python для генерации, импорта и проверок данных;
- SQLite;
- Cloudflare Pages;
- Cloudflare Workers / D1 как подготовленный динамический вариант;
- GitHub Actions;
- Wrangler;
- статический HTML, CSS и vanilla JavaScript без frontend-фреймворка.

## Основные сущности

Упрощённая модель:

```text
competitions ──< categories ──< results >── athletes
     │               │              │
  protocols      discipline      result_reps
                                     │
                                  persons
                                     │
                         coach / athlete / judge
```

Основные таблицы:

| Таблица | Назначение |
| --- | --- |
| `competitions` | соревнования |
| `categories` | дисциплина, пол, возраст, весовая категория, вес гири и регламент |
| `results` | отдельные строки протокола |
| `result_reps` | разбивка подъёмов по упражнениям и рукам |
| `athletes` | роль спортсмена и исторические спортивные данные |
| `persons` | каноническая карточка человека |
| `person_coach_mentions` | исторические связи тренер–спортсмен |
| `person_coach_aliases` | варианты написания тренеров в протоколах |
| `protocols` | исходные документы и их статус |
| `edits` | редакционные исправления |
| `issues` | обнаруженные проблемы данных |

Подробности находятся в [`docs/schema.md`](docs/schema.md).

## Поток данных

### 1. Источник

Исходниками служат официальные или опубликованные организаторами протоколы соревнований.

Оригинальные ссылки и архивные копии по возможности сохраняются вместе с соревнованием.

### 2. Извлечение

Данные переводятся в структурированный JSON:

```text
data/<competition-slug>.json
```

Для сканов может использоваться OCR, но OCR не считается надёжным источником числовых результатов без дополнительной сверки.

### 3. Нормализация

Генераторы:

- сопоставляют регионы со справочником;
- разрешают известные алиасы;
- применяют подтверждённые merge персон;
- сохраняют raw-значения;
- строят производные связи спортсменов, тренеров и персон.

### 4. Проверки

Перед публикацией выполняются проверки структуры и качества данных.

Отдельные правила используются для:

- дублей спортсменов;
- неоднозначных персон;
- регионов;
- тренеров;
- весовых категорий;
- ошибок и редакционных исправлений.

### 5. Сборка

Из миграций и данных создаётся локальная SQLite-база, после чего все публичные страницы заранее рендерятся в `dist/`.

### 6. Deployment

Merge в `main` запускает GitHub Actions:

```text
main
  → npm run build
  → dist/
  → Wrangler
  → Cloudflare Pages
  → vsegiri.com
```

GitHub Pages используется как резервный/preview-вариант и не является основным production deployment.

## Быстрый старт

Требуются Node.js, Python 3 и SQLite.

Установить зависимости:

```sh
npm install
```

Собрать локальную базу:

```sh
npm run db:local
```

Проверить базу:

```sh
npm run db:check
```

Собрать статический сайт:

```sh
npm run build
```

Запустить локальный preview:

```sh
npm run preview
```

После этого сайт доступен на:

```text
http://localhost:8080
```

## Полезные команды

```sh
npm run db:local        # собрать локальную SQLite-базу
npm run db:check        # проверить сборку и данные
npm run build           # собрать production static site
npm run preview         # build + локальный HTTP-сервер
```

Cloudflare/D1-команды в `package.json` сохранены для динамической версии и служебных задач.

## Правила изменения данных

### Не редактировать generated SQL вручную

Основной источник данных — `data/*.json` и справочники.

Правильный поток:

```text
data/*.json
   ↓
generator
   ↓
seeds / local SQL
   ↓
SQLite
   ↓
site
```

Если изменить только generated SQL, изменение будет потеряно при следующей генерации.

### Сохранять raw-данные

Исправление канонического имени, региона или другой сущности не должно уничтожать значение, которое реально было напечатано в протоколе.

### Ошибки источника — не ошибки импорта

Если в официальном протоколе указано неверное значение, оно фиксируется как ошибка первоисточника и корректируется через специальный механизм. Сам протокол остаётся доступным для проверки.

### Эстафеты и командные результаты

Такие категории могут присутствовать в источнике, но часть из них пока откладывается от детальной оцифровки. Отложенная категория сохраняется в структуре данных, чтобы не потерять факт её существования.

## Статус проекта

Проект активно развивается и архив ещё не является полным.

Главный приоритет — не максимальное количество строк, а **проверяемая историческая база**, которую можно постепенно расширять, не теряя происхождение данных и возможность исправлять ошибки.
