# Гиревой архив

Публичный архив результатов соревнований по гиревому спорту.
Данные извлекаются из PDF-протоколов моделью, администратор проверяет и публикует.

- `docs/decisions.md` — принятые решения и правки к требованиям
- `docs/schema.md` — пояснения к схеме
- `docs/roadmap.md` — план реализации по шагам
- `migrations/0001_init.sql` — схема D1
- `seeds/` — справочники и данные протоколов
- `data/` — данные протоколов, извлечённые из PDF (источник для сидов)
- `scripts/gen_seed.py` — генератор сида из `data/*.json`
- `scripts/ocr_pdf.py` — распознавание протоколов-сканов

## Быстрый старт

```sh
npm run db:local     # локальная база SQLite со схемой, справочниками и протоколами
sqlite3 .local/girevoy.db
```

На Cloudflare:

```sh
npm run db:create    # id из вывода вписать в wrangler.toml
npm run db:migrate
npm run db:seed
```

## Демо на GitHub Pages

`.github/workflows/pages.yml` собирает статический снимок при каждом
пуше в ветку по умолчанию. Чтобы он заработал, один раз включите Pages:
**Settings → Pages → Source → GitHub Actions**.

Это витрина интерфейса. Рабочий сайт живёт на Cloudflare: там страницы собираются
из D1 тем же кодом (`src/render.js`), а Pages отдаёт только заранее отрендеренный
снимок — админки, поиска по базе и свежих данных на нём нет.

## Данные

`data/chempionat-rossii-2026.json` — чемпионат России 2026 (2–6 июня, Новосибирск),
**только длинный цикл**: 11 категорий, 100 результатов, 100 спортсменов.
Эстафеты (стр. 13–16 протокола) внесены как отложенные категории (решение 3, FR-C7).
Остальные разделы протокола — толчок, рывок, жонглирование, командный зачёт — не оцифрованы.

Правки вносятся в JSON, потом `npm run seed:gen` пересобирает
`seeds/0003_chempionat-rossii-2026.sql`. Руками SQL не править.

Данные извлечены из скана моделью; сверка человеком не проводилась, поэтому
`results.verified_by` пуст.

## Извлечение из PDF

Протоколы приходят сканами без текстового слоя. Инструменты ставит
`scripts/setup_env.sh` (poppler-utils, tesseract с русским, sqlite3); он же висит
на хуке `SessionStart` в `.claude/settings.json`, так что в новой сессии всё на месте.

```sh
python3 scripts/ocr_pdf.py протокол.pdf --titles      # шапки страниц: где какая дисциплина
python3 scripts/ocr_pdf.py протокол.pdf --pages 2-16  # распознать нужные страницы
```

`--titles` надёжно отвечает на вопрос «что на какой странице». Числа в строках OCR
путает (`62,800` → `6240`), поэтому результаты и личный вес всё равно сверяются
глазами по странице — это тот самый второй прогон из FR-A17.
