# План реализации

`docs/roadmap.md` — **единственный источник правды по плану развития проекта**.

Все новые продуктовые идеи, технические задачи и изменения приоритетов сначала
добавляются сюда. GitHub Issues и PR используются для выполнения конкретных пунктов
roadmap и не должны становиться отдельным параллельным backlog.

Обозначения:

- ✅ выполнено;
- 🟡 выполнено частично / требует завершения;
- ⬜ не начато или ещё не доведено до требуемого результата.

Оценки в шкале документа требований: S — до дня, M — 1–3 дня, L — неделя и больше.

- [ ] регрессии merge/alias: старые slug ведут на ту же персону после слияния, результаты

- [ ] инварианты БД (`PRAGMA foreign_key_check`, отсутствие dangling-ссылок,

- [ ] регрессии по реальным случаям из `ERRATA.md`.

**Готово, когда:** CI собирает чистую базу из всех `data/*.json`, прогоняет инварианты и

## Правило ведения roadmap

1. Новая идея или задача сначала добавляется в этот файл.
2. Если задача достаточно конкретная для реализации, под неё можно открыть Issue/PR.
3. После merge соответствующий пункт roadmap сразу отмечается выполненным или обновляется.
4. Закрытые Issues не считаются историей плана: история плана живёт в git-истории этого
   файла.
5. `ERRATA.md` остаётся отдельным источником известных ошибок **в данных**, а не backlog
   разработки.
