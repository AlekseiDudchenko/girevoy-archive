# SEO-план: протоколы и результаты гиревого спорта

Цель: сделать `vsegiri.com` основным поисковым источником по протоколам и результатам соревнований по гиревому спорту, а также собирать длинный хвост запросов по соревнованиям, спортсменам, тренерам, регионам и годам.

## Основная стратегия

Не ограничиваться запросом «протоколы по гиревому спорту». Архив должен закрывать четыре группы спроса:

1. **Протоколы и результаты**
   - протоколы по гиревому спорту;
   - результаты гиревой спорт;
   - результаты соревнований по гиревому спорту.

2. **Конкретные соревнования**
   - Кубок России по гиревому спорту 2026 результаты;
   - Кубок России 2026 протокол;
   - Чемпионат России по гиревому спорту 2026 результаты;
   - аналогичные запросы по федеральным округам и первенствам.

3. **Персоны**
   - фамилия + гиревой спорт;
   - фамилия + результаты;
   - фамилия + конкретный турнир/год.

4. **Длинный хвост**
   - регион + гиревой спорт;
   - год + результаты;
   - дисциплина / весовая категория + результаты;
   - тренер + спортсмены / результаты.

## Технические правила

1. Основной домен — `https://vsegiri.com`.
2. Важные данные должны присутствовать в исходном HTML и не зависеть от выполнения JavaScript.
3. Каждый индексируемый URL должен иметь уникальные title, description и H1.
4. Фильтры/сортировки не должны порождать бесконечное пространство индексируемых URL.
5. Sitemap строится автоматически из реально сгенерированных страниц.
6. Старые URL нельзя ломать: при переходе на новую структуру нужны 301.
7. Новые импорты соревнований должны автоматически обновлять sitemap и связанные страницы.

## Первичный аудит — 19.09.2026

### Что уже хорошо

- Production собирается как статический сайт.
- Страницы соревнований, персон и результатов содержат основные данные непосредственно в HTML.
- Для страниц уже задаются `<title>` и meta description.
- Production deployment идёт через Cloudflare Pages после merge в `main`.

### Найденные проблемы

- По проверенным запросам `site:vsegiri.com` поисковая выдача не вернула результатов.
- В репозитории отсутствовал `robots.txt`.
- В репозитории отсутствовал `sitemap.xml`.
- В общем HTML-шаблоне отсутствует canonical.
- Текущие статические URL технические (`c-*.html`, `p-*.html`, `a-*.html`), что не блокирует индексацию, но требует отдельной миграции для более сильной SEO-структуры.
- Доступ к production-домену через используемый поисковый инструмент сейчас не сработал, поэтому HTTP-заголовки и фактическую выдачу `robots.txt`/sitemap после deploy нужно повторно проверить внешним запросом и через панели вебмастеров.

### 404 и защита от soft-404

Cloudflare Pages при отсутствии верхнеуровневого `404.html` применяет SPA fallback и может отдавать корневую страницу для неизвестных путей. Поэтому сборка теперь:
- генерирует отдельный `404.html`;
- ставит на нём `noindex, nofollow`;
- исключает `404.html` из sitemap;
- проверяет это в build.

Фактические HTTP-коды production URL нужно подтвердить после деплоя, потому что из текущей среды `vsegiri.com` не резолвится.

### SEO-шаблоны и structured data

Реализовано в текущем SEO-пакете:
- главная ориентирована на запросы «протоколы» и «результаты соревнований по гиревому спорту»;
- страница «Все результаты» получила целевой title, description и H1;
- соревнования получают уникальные title/description с названием, датой, городом и объёмом данных;
- страницы спортсменов и тренеров получают role-aware title/description;
- страницы соревнований и персон получили видимые хлебные крошки и `BreadcrumbList`;
- страницы соревнований получили `SportsEvent`;
- добавлены OpenGraph/Twitter metadata и абсолютный `og:url`.

Кубок России 2026 пока отсутствует в `data/protocols.json`. До импорта создана временная индексируемая посадочная `c-kubok-rossii-2026.html` с сообщением «Данные обрабатываются» и статистикой «подсчитываем». После импорта реального протокола обычный генератор соревнований автоматически заменит плейсхолдер полноценной страницей.

### Canonical URL

Реализовано:
- каждая статическая индексируемая страница получает абсолютный canonical на `https://vsegiri.com`;
- технические дубли спортсменов `a-*.html` канонизируются на соответствующие `p-*.html`;
- `a-*.html` исключаются из sitemap, чтобы поисковику не предлагались одновременно дубль и canonical;
- query-параметры клиентских фильтров не входят в canonical, поскольку canonical зашит в статический HTML.

### Первый шаг реализации

В этой ветке:
- добавляется `robots.txt`;
- при статической сборке автоматически создаётся `sitemap.xml` из всех реально сгенерированных HTML-страниц;
- sitemap указывается в robots;
- следующий шаг — canonical и проверка Search Console / Яндекс Вебмастер.
