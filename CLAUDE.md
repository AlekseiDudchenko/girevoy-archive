# Гиревой архив

Публичный архив протоколов соревнований по гиревому спорту. Данные извлекаются из PDF
языковой моделью, администратор сверяет и публикует. Читатели анонимны.

Требования и разбор: `docs/decisions.md`, `docs/schema.md`, `docs/roadmap.md`.
Порядок работ — по `docs/roadmap.md`: сначала извлечение и автопроверки, интерфейс позже.

## Главный риск

Модель ошибается в цифрах молча: «112» вместо «142» выглядит правдоподобно. Числа —
весь смысл продукта, один найденный фанатами неверный результат обесценивает базу.
Отсюда: ни одна строка не публикуется без автопроверок и двойного извлечения, человек
остаётся в контуре, исходный PDF всегда рядом с данными.

## Схема

Точные определения — `migrations/0001_init.sql`, обоснования — `docs/schema.md`.
Ниже карта, чтобы не читать DDL целиком.

```
competitions ──< categories ──< results >── athletes
     │               │              │
  protocols      дисциплина     result_reps (подъёмы по упражнениям и рукам)
     │           вес снаряда
extraction_runs  руки, минуты
     │           весовая кат.
   issues        зачёт по уровню
```

**Ядро**

| Таблица | Что хранит |
| :- | :- |
| `competitions` | турнир: slug, даты, город, страна, ранг, федерация, ссылка на первоисточник, `is_published` |
| `categories` | разрез внутри турнира, в котором разыгрываются места: дисциплина × пол × возраст × зачёт × вес снаряда × `hands` × регламент × весовая категория. `is_deferred = 1` — раздел протокола не оцифрован |
| `results` | строка протокола: место, `total_reps` или `points`, `result_value` (генерируемая — по ней сортировка), личный вес, продублированный ключ серии, сырые значения из PDF, происхождение |
| `result_reps` | подъёмы: `result_id` × упражнение × рука. Отдельной таблицей, потому что набор дисциплин открытый |
| `athletes` | ФИО, год рождения, регион, клуб, тренер, разряд, `merged_into_id` для обратимого слияния |
| `athlete_slugs` | все адреса, которые когда-либо вели на спортсмена — держит устойчивые URL при слиянии и переименовании |

**Конвейер**

| Таблица | Что хранит |
| :- | :- |
| `protocols` | исходный PDF в R2 и статус: `uploaded → extracted → verified → published` либо `rejected` с причиной |
| `extraction_runs` | два независимых прогона распознавания, `raw_json` как есть — форма меняется с промптом |
| `issues` | проблемы, привязанные к строке: `place_order`, `row_count`, `body_weight`, `duplicate`, `implausible`, `run_mismatch`. Публикация запрещена, пока есть `status = 'open'` |
| `edits` | история правок, заведена заранее — задним числом её не восстановить |

**Справочники**: `disciplines` (только упражнения), `age_groups`, `divisions`
(любители / профессионалы / новички), `sport_ranks` (ЕВСК), `competition_ranks`,
`federations`, `regions`, `clubs`. У клубов и регионов есть таблицы алиасов —
в протоколах один клуб пишется пятью способами.

Весовые категории справочником не нормализуются: хранятся как в протоколе.

## Извлечение из PDF

Протоколы приходят сканами без текстового слоя: `pdftotext` на них даёт пустоту.
Инструменты ставит `scripts/setup_env.sh`, он же на хуке `SessionStart`.

```sh
python3 scripts/ocr_pdf.py протокол.pdf --titles      # где какая дисциплина
python3 scripts/ocr_pdf.py протокол.pdf --pages 2-16  # распознать страницы
```

`--titles` надёжно отвечает, что на какой странице, и экономит чтение сорока страниц
целиком. Числа OCR путает (`62,800` → `6240`), поэтому результаты и личный вес
сверяются по картинке страницы — это и есть второй прогон из FR-A17.

Извлечённое кладётся в `data/<slug>.json`, сид собирается `npm run seed:gen`.
SQL руками не правится.

## Решения, которые нельзя нарушать

Полный список с обоснованиями — `docs/decisions.md`. Кратко:

- **Дисциплина — это только упражнение.** Число рук (`hands`), регламент (`time_limit_min`)
  и зачёт по уровню (`division_id`) — параметры категории. Не заводить дисциплину
  «длинный цикл одной рукой 30 минут».
- **Очки двоеборья не считаются.** Формула нигде не хранится, `points` распознаётся из
  протокола как обычное число. Защита — расхождение двух прогонов извлечения.
- **Весовая категория хранится как в протоколе** (`weight_class_raw`), плюс разобранные
  `weight_class_kg` и признак «+». Версионного справочника категорий по годам нет.
- **Рекордов нет** — ни личных, ни страницы рекордов. Понятия «номинация» в коде быть
  не должно.
- **Ключ серии** — дисциплина × вес снаряда × число рук × регламент. Результаты разных
  серий несравнимы: не соединять линией на графике, не сортировать в одной таблице.
  Поля ключа продублированы в `results` ради фильтров — их синхронность держит импорт.
- **Дубли спортсмена внутри категории** ловит автопроверка, а не `UNIQUE`: протокол
  может содержать ошибку составителя, и её надо суметь сохранить.
- **Сырьё рядом с нормализованным.** `raw_name`, `raw_club`, `raw_region` — то, что
  написано в PDF. Не выбрасывать при сопоставлении со справочниками.
- **Эстафета и командный зачёт вне MVP**, но категория заводится с `is_deferred = 1`
  и показывается с пометкой «будет добавлено позже».

## Интерфейс

Один код рендеринга обслуживает Worker и статический снимок — не разводить их.
Цвета только через токены в `public/style.css`, светлая и тёмная тема. Числа в таблицах
классом `.n` (моноширинный, табличные цифры, без переносов). Широкие таблицы — в
контейнере со `overflow-x`. Рядом с любым результатом видны его условия: дисциплина,
вес снаряда, регламент.

Перед коммитом страницы — посмотреть скриншот, а не только собранный HTML.

## Данные — настоящие

Демо-данные удалены: в базе только реальные протоколы. Не придумывать результаты и не
заводить вымышленных спортсменов — теперь всё, что лежит в базе, читается как факт
о реальном человеке.

Чего пока нет: строку публикует модель, а не человек. `results.verified_by` пуст,
и обещание главной страницы «числа сверены с оригиналом протокола» держится только
на автопроверках FR-A5 и внимательности при извлечении.
