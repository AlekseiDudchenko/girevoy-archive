# Гиревой архив

Публичный архив протоколов соревнований по гиревому спорту. Данные извлекаются из PDF
языковой моделью, администратор сверяет и публикует. Читатели анонимны.

Требования и разбор: `docs/decisions.md`, `docs/schema.md`, `docs/roadmap.md`.
Порядок работ — по `docs/roadmap.md`: сначала извлечение и автопроверки, интерфейс позже.

## Главный риск

Модель ошибается в цифрах молча: «112» вместо «142» выглядит правдоподобно. Числа —
весь смысл продукта, один найденный фанатами неверный результат обесценивает базу.
Отсюда: ни одна строка не публикуется без автопроверок и двойного извлечения, человек
остаётся в контуре, исходный PDF всегда рядом с данными.

## Структура

```
migrations/     схема D1 (SQLite)
seeds/          справочники + демо-данные (генерируются scripts/gen_demo.py)
src/queries.js  запросы, адаптер даёт all()/get() — работает с D1 и node:sqlite
src/render.js   HTML всех публичных страниц, чистые функции
src/worker.js   Cloudflare Worker поверх D1
scripts/        генератор демо-данных, статический снимок сайта
public/         style.css
```

## Команды

```sh
npm run db:local    # собрать .local/girevoy.db из миграции и сидов
npm run snapshot    # отрендерить сайт в dist/
npm run preview     # то и другое + сервер на :8080
npm run demo:gen    # перегенерировать seeds/0002_demo.sql (детерминированно)
```

## Решения, которые нельзя нарушать

Полный список с обоснованиями — `docs/decisions.md`. Кратко:

- **Дисциплина — это только упражнение.** Число рук (`hands`), регламент (`time_limit_min`)
  и зачёт по уровню (`division_id`) — параметры категории. Не заводить дисциплину
  «длинный цикл одной рукой 30 минут».
- **Очки двоеборья не считаются.** Формула нигде не хранится, `points` распознаётся из
  протокола как обычное число. Защита — расхождение двух прогонов извлечения.
- **Весовая категория хранится как в протоколе** (`weight_class_raw`), плюс разобранные
  `weight_class_kg` и признак «+». Версионного справочника категорий по годам нет.
- **Рекордов нет** — ни личных, ни страницы рекордов. Понятия «номинация» в коде быть
  не должно.
- **Ключ серии** — дисциплина × вес снаряда × число рук × регламент. Результаты разных
  серий несравнимы: не соединять линией на графике, не сортировать в одной таблице.
  Поля ключа продублированы в `results` ради фильтров — их синхронность держит импорт.
- **Дубли спортсмена внутри категории** ловит автопроверка, а не `UNIQUE`: протокол
  может содержать ошибку составителя, и её надо суметь сохранить.
- **Сырьё рядом с нормализованным.** `raw_name`, `raw_club`, `raw_region` — то, что
  написано в PDF. Не выбрасывать при сопоставлении со справочниками.
- **Эстафета и командный зачёт вне MVP**, но категория заводится с `is_deferred = 1`
  и показывается с пометкой «будет добавлено позже».

## Интерфейс

Один код рендеринга обслуживает Worker и статический снимок — не разводить их.
Цвета только через токены в `public/style.css`, светлая и тёмная тема. Числа в таблицах
классом `.n` (моноширинный, табличные цифры, без переносов). Широкие таблицы — в
контейнере со `overflow-x`. Рядом с любым результатом видны его условия: дисциплина,
вес снаряда, регламент.

Перед коммитом страницы — посмотреть скриншот, а не только собранный HTML.
